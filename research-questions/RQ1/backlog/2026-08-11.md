**Designed `RequestedCpus` together, then implemented it**
- Design: a new optional `RequestedCpus []int` field. If `len(requested) <= count`, every requested cpu is guaranteed *if it fits* (validated first, committed only after all pass — never partially commit then fail), and the rest is filled by worst-fit as before. If `len(requested) > count`, worst-fit picks the best `count` among just the requested candidates (covers both the "exact pin" and "any of these N, pick the best" use cases the placement logic actually needs). If a requested cpu can't fit, fail loudly and name which one and why — not silent fallback. Driver stays completely topology-blind; the caller (harness) is responsible for knowing which cpus to ask for.
- Implementation: added the field to `RtClaimParametersSpec`, the CRD YAML schema, regenerated codegen (`controller-gen`/`client-gen` — needed installing both tools, then working through a `make generate` deadlock where a failed `client-gen` run had already deleted the generated clientset package before `go mod vendor` could run again, requiring the client-gen step be run standalone once to break the cycle), rewrote `allocate()`'s per-claim logic into a three-way switch (`len(requested) > count` / `len(requested) > 0` / plain worst-fit), pulled the repeated "commit one cpu" logic into a shared `commitCpu` helper, and wired the new error path through `UnsuitableNode` (previously swallowed entirely — `allocate(...)`'s error return was silently discarded both inside `allocate()` itself and at its call site).
- Code review pass caught: dead/commented-out exploration code left inside `Allocate()` (removed), `gofmt` formatting drift, and confirmed `go vet`'s lock-copy warnings on `NodeAllocationState` are pre-existing (a bare `sync.RWMutex` embedded in the struct) and unrelated to this change.
